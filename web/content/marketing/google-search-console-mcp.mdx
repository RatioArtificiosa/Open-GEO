Most Google Search Console (GSC) MCP servers are open source, but they take a lot of effort to set up. You need to create a Google Cloud project, enable an API, build an OAuth client, download a `credentials.json`, then keep a local server running. OpenGeo handles the Google connection for you. You sign up, connect your property, and start asking.

## Setup: no Google Cloud project

1. Sign up for OpenGeo ($10/month).
2. Go through the onboarding. When prompted, click **Connect Search Console** and pick your property.
3. Add the OpenGeo MCP endpoint to your client (steps below) and approve the OpenGeo login when prompted.

The hosted MCP server URL is:

```txt
https://app.opengeo.so/mcp
```

### Claude Code

```bash
claude mcp add --transport http --scope user opengeo https://app.opengeo.so/mcp
```

### Claude Desktop

1. Open Customize → Connectors.
2. Click **Add** (or **+**), then choose **Add custom connector**.
3. Paste `https://app.opengeo.so/mcp`.

### Cursor

1. Open Cursor Settings → Tools & Integrations → MCP Tools.
2. Click **New MCP Server** (this opens `mcp.json`) and add:

```json
{
  "mcpServers": {
    "opengeo": {
      "url": "https://app.opengeo.so/mcp"
    }
  }
}
```

### Codex CLI

```bash
codex mcp add opengeo --url https://app.opengeo.so/mcp
```

Any other MCP client works the same way: add `https://app.opengeo.so/mcp` as a remote server and sign in. Full setup and troubleshooting live in the [MCP docs](/docs/mcp).

### The DIY way (every other GSC MCP)

1. Create a Google Cloud project
2. Enable the Search Console API
3. Configure the OAuth consent screen
4. Create OAuth client credentials
5. Download `credentials.json`
6. Install and run a local MCP server

## What your agent can read

Two read-only tools over the property you connect. Both pull Google's own numbers, and neither uses credits.

**Search performance.** Clicks, impressions, CTR, and average position for your site, sliced by query, page, country, device, and date. Pull up to 16 months of history in a single question.

**URL inspection.** Whether a page is indexed and, if not, why: coverage status, last crawl, the canonical Google chose versus the one you declared, plus mobile and rich-result checks. Up to 10 URLs at a time.

The agent can read and inspect. It cannot change anything in your account.

## FAQ

### What does it cost?

The Search Console MCP tools are included with the $10/month OpenGeo plan (which comes with a 30-day money-back guarantee) and use zero credits. OpenGeo's other tools (keyword research, rank tracking, backlinks) use the usage credits included with the plan, through the same endpoint — and the $10 plan includes $10 of usage, so the first month is covered before you pay anything more.

### Is it open source?

Yes — MIT, including the Search Console MCP. **And the honest part is what that costs you.** The one-click connection here uses OpenGeo's hosted Google app. Self-host, and you bring your own Google OAuth client: the same Cloud-console step, the same client-secret handling, and the same callback configuration, on whatever machine you run it on.

That step is the entire difference. It is a ten-minute job once and a chore every time anything changes, and it is the part of this page you would be doing instead of the work you came here for.

If you want the data to never touch our account, that is a legitimate reason to self-host, and we would rather you chose it than chose badly.

### Is it read-only?

Yes. OpenGeo requests read-only access (`webmasters.readonly`). Your agent can read performance data and inspect URLs, but it can't change your account.

### Which AI clients work?

Any MCP client, including Claude Code, Claude Desktop, Cursor, Codex, and OpenClaw. Add the OpenGeo MCP endpoint and sign in.

### How fresh is the data?

It's Google's own data, so the most recent few days can be incomplete. History runs back 16 months, the same as the Search Console interface.
